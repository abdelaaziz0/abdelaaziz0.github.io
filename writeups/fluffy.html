01 - Environment & Scope

Environment & Scope

Fluffy exposes a single Windows Domain Controller externally. The provided credential j.fleischman:J0elTHEM4n1990! is not a shell by itself, but it is enough to enumerate SMB shares and write to the IT share. That share is the opening. It contains a PDF warning the IT department about several 2025 vulnerabilities, and one of them gives us a way to coerce a second domain user into authenticating to our SMB listener.

Host IP Role Notes
Kali / Exegol 10.10.14.241 Attack box VPN interface tun0
DC01 10.129.31.202 Domain Controller fluffy.htb
Clock Skew Nmap showed the DC clock was exactly seven hours ahead of the attacker machine. Kerberos operations failed with KRB_AP_ERR_SKEW until the process was executed in a faketime shell aligned to the DC time.
Account Secret Type How Obtained
j.fleischman J0elTHEM4n1990! Plaintext Given credential

04 - Intelligence from the PDF

Patch Notice & CVE Selection

The PDF is not flavor text. It tells us which vulnerability family is relevant and, since the share is writable, raises the question: can we place a crafted file that coerces authentication from whoever processes it?

CVE ID Severity Usage
CVE-2025-24071 Critical Used - crafted archive coerces SMB authentication
CVE-2025-24996 Critical Listed, not used in this path
CVE-2025-46785 High Listed, not used in this path
CVE-2025-29968 High Listed, not used in this path
CVE-2025-21193 Medium Listed, not used in this path
CVE-2025-3445 Low Listed, not used in this path
Why CVE-2025-24071 No code execution needed on the target - only a crafted file that triggers outbound SMB authentication when processed (indexed, rendered, scanned). Perfect for a writable internal share touched by other users.

Two attributes matter: winrm_svc is a service account in Remote Management Users. If we obtain its hash, WinRM gives us a user shell. A password reset attempt failed - the path is certificate-based takeover instead.

GenericWrite & self-membership

The useful edge is the cascade: p.agila can self-add to Service Accounts, and that group has GenericWrite over winrm_svc and ca_svc. That is enough to write msDS-KeyCredentialLink and take the accounts through Shadow Credentials.

p.agila

Membership

Self-add to Service Accounts

The group edge allows p.agila to join the target group.

Write primitive

GenericWrite over service users

winrm_svc and ca_svc expose writable key credentials.

Takeover

Shadow Credentials

Write msDS-KeyCredentialLink, authenticate with PKINIT, recover NT hash.

09 - Account Takeover

Shadow Credentials to winrm_svc

Shadow Credentials

With write access to msDS-KeyCredentialLink, Certipy adds a public key to the target account, authenticates with the matching private key via PKINIT, then uses the Kerberos material to recover the NT hash. The account password is never changed.

Key material

Generate keypair

Certipy creates the private key and public credential material.

Directory write

Write msDS-KeyCredentialLink

The public key is attached to winrm_svc.

PKINIT

Authenticate with the PFX

The KDC validates the stored public key and issues a TGT.

Impact

Recover hash and use WinRM

Certipy recovers the NT hash, then Pass-the-Hash gives remote access.

Step 1 - Add p.agila to Service Accounts

bloodyAD --host 10.129.31.202 -d fluffy.htb \
  -u 'p.agila' -p '[redacted]' \
  add groupMember "Service Accounts" p.agila

[+] p.agila added to Service Accounts

Step 2 - Write Shadow Credential on winrm_svc

certipy shadow add \
  -u 'p.agila@fluffy.htb' -p '[redacted]' \
  -account 'winrm_svc' \
  -dc-ip 10.129.31.202 \
  -dc-host DC01.fluffy.htb \
  -target DC01.fluffy.htb \
  -target-ip 10.129.31.202 \
  -out winrm_svc

[*] Successfully added Key Credential with device ID 'e82407fe...'
[*] Saved certificate and private key to 'winrm_svc'
Clock skew - faketime shell required The auto mode reached PKINIT but failed with KRB_AP_ERR_SKEW. The fix was to split the operation: write the Shadow Credential with shadow add, open a faketime shell adjusted to the DC time, then run certipy auth from inside it.

faketime "$(date -d '+7 hours' '+%Y-%m-%d %H:%M:%S')" zsh

Step 3 - Authenticate with the PFX (in faketime shell)

certipy auth \
  -pfx winrm_svc \
  -username winrm_svc \
  -domain fluffy.htb \
  -dc-ip 10.129.31.202

[*] Using principal: 'winrm_svc@fluffy.htb'
[*] Trying to get TGT...
[*] Got TGT
[*] Got hash for 'winrm_svc@fluffy.htb': [redacted]

The certificate had no embedded identity, but Certipy used the supplied principal. PKINIT succeeded and the NT hash was recovered via the resulting Kerberos material.

11 - Post-User Pivot

Shadow Credentials to ca_svc

The next target was ca_svc, a certificate authority service account. CA service accounts often have enrollment permissions that make AD CS abuse possible. LDAP shows it is a member of Cert Publishers and has an existing userCertificate attribute.

Tool note - NT hash authentication Certipy uses -hashes for NT hash auth. Passing :hash with -p treats it as a literal password and fails with invalidCredentials. 
certipy shadow add \
  -u 'winrm_svc@fluffy.htb' -hashes ':[redacted]' \
  -account 'ca_svc' \
  -dc-ip 10.129.31.202 \
  -dc-host DC01.fluffy.htb \
  -target DC01.fluffy.htb \
  -target-ip 10.129.31.202 \
  -out ca_svc

[*] Successfully added Key Credential with device ID '8cdc1fdf...'
[*] Saved certificate and private key to 'ca_svc'

12 - Privilege Escalation

AD CS ESC16 to Administrator

AD CS ESC16

Certipy found the CA security extension disabled. Without the SID extension, the KDC falls back to UPN mapping, so a certificate issued while ca_svc's UPN is temporarily administrator maps to Administrator instead of the service account.

Normal state

Security extension active

SAN UPN
administrator
SID ext
S-1-5-21-...-1103, real SID of ca_svc
KDC result
Uses the SID and authenticates ca_svc.
ESC16

Security extension disabled

SAN UPN
administrator
SID ext
Absent
KDC result
Falls back to UPN mapping and authenticates Administrator.
UPN write

winrm_svc sets ca_svc UPN to administrator.

Enroll

ca_svc requests a User certificate.

Restore

winrm_svc restores ca_svc@fluffy.htb.

PKINIT

administrator.pfx maps to Administrator and yields TGT + NT hash.

14 - Summary

Full Attack Chain

Initial credential

j.fleischman:J0elTHEM4n1990!

SMB auth succeeds, admin shares are closed, and IT is READ/WRITE.

Signal

Writable IT share + patch notice

Upgrade_Notice.pdf lists CVE-2025-24071 as critical and the share accepts uploads.

Coercion

CVE-2025-24071 archive

poc.py creates fluffy.ms-library inside exploit.zip, pointing to the attacker SMB listener.

Capture

Responder receives NetNTLMv2

The target processes the file and authenticates to attacker SMB as FLUFFY\p.agila.

Crack

Hashcat mode 5600

p.agila's password is recovered with rockyou.txt.

ACL abuse

Service account group path

p.agila joins Service Accounts, gaining write access to key credentials on winrm_svc.

Account takeover

Shadow Credentials to winrm_svc

Certipy writes msDS-KeyCredentialLink; PKINIT with faketime retrieves the NT hash.

User shell

WinRM Pass-the-Hash

winrm_svc is in Remote Management Users, so WinRM yields user.txt.

Pivot

Shadow Credentials to ca_svc

winrm_svc writes key credentials to ca_svc and recovers its NT hash.

AD CS

ESC16 UPN mapping

The CA has the security extension disabled; ca_svc is temporarily mapped to administrator for certificate enrollment.

Domain admin

Administrator hash and root flag

administrator.pfx authenticates through PKINIT, then WinRM Pass-the-Hash reads root.txt.
